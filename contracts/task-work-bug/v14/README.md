# Portable owned text edits v14

Published v13 bytes remain immutable. v14 preserves its owner, source revision, branch/HEAD, tracked mode, no-hooks, Native-host rejection, isolated index and inspect-before-replay boundaries. Task body and wait policy remain v13; lifecycle/settlement are unchanged. Native must advertise and implement its own grant-bound adapter; installing these files grants no new authority.

`owned-edit-cli.mjs --root <canonical-root> --operation capture|apply|preview|commit|inspect --request <plain-json-file>` retains the v13 request fields and approval-digest contract. Read the v13 instructions for authorization and semantic independence. This tool never treats an agent verification string as actual test evidence.

Before capture creates private journal storage, and before apply changes a file or captured receipt, v14 requires valid Unicode UTF-8 text with no NUL and at most 1,048,576 UTF-8 bytes for before/after content. The exact serialized sealed receipt, including the 64-byte hex MAC and metadata, must be at most 4,194,304 bytes, matching the reader limit. UTF-16 replacement length alone is insufficient. Exact byte limits are accepted; exceeding a limit fails before the affected write. `invalid_edit_text`, `owned_edit_text_too_large` and `owned_edit_receipt_too_large` identify these rejections.

Every save rechecks the same limits. Commit preflights both terminal receipt shapes before index/temp/object writes, including verification text and repository object-ID lengths. Rejected apply/commit requests preserve file content, existing readable receipt, HEAD and index. Capture budget rejection creates no edit storage or integrity key. Normal partial failures retain the original applying/committing evidence and require inspect; v14 does not migrate, repair or replay an oversized v13 journal. Same-user hostile filesystem races and semantic independence remain host responsibilities.

The v14 verifier pins the v13 manifest and actual verifier code before loading that verifier, then rechecks every immutable v13 file and its pinned dependencies. A v13 task-body, execution-policy or checker byte change is rejected before a project operation. This is not protection against same-account tampering between verification and module loading, or arbitrary malicious top-level module execution. Authenticity still depends on the approved Pack and host.
