# Canonical Incident registration v16

Opt-in Incident-only successor of v15 ticket registration. Task/Work/Bug and Task batch registration stay on immutable v15. Existing nested ticket v9 intent schema, semantic digest, canonical-main resolver, final number allocation, exact registration commit, journal and replay are preserved. Only Incident output changes: issueKind and all canonical Incident fields are top-level, matching the separately versioned zuz-its/v5 strict parser. Optional mitigation/recovery serialize null. No body example supplies header fields.

Run register-ticket.mjs with --root, --intent and --dry-run, then the same approved digest with --write. The installed v16 manifest and actual pinned v15/v5 dependency bytes must validate. Both preview and write validate generated bytes with the actual v5 parser before any journal, record, directory or commit mutation. Unknown fields, invalid impact/classification/date, malformed arrays and non-Incident intent reject. Existing noncanonical Incident records and replay commits reject without migration or a positive receipt; user review/update is required.

The v15 registration lock is reused unchanged: at most 300000ms live-owner waiting, SIGINT/SIGTERM cancellation, preserve dead-owner/unknown locks, release only matching inode+owner bytes. This is local coordination, not an OS-account security boundary. Native sessions never use this external route. v16 registration is not v5 lifecycle, v14 owned edit, v13 Task body/wait, settlement, publication or installation authority. Package adoption and explicit profile selection remain required. Published v1-v15 and zuz ITS v1-v4 bytes stay immutable.

Supported UTC ISO timeline values retain their exact instants and fractional precision. The producer aligns the four timeline fields to the maximum supplied fractional width using zero padding only, then checks exact chronological order; nested semantic intent strings and digest stay unchanged. This avoids mixed-precision lexical ambiguity without requiring callers to use one precision.

Recovery and replay are limited to the Incident namespace: only docs/work-items/incidents/INC-* journal/commit paths are eligible. Foreign Work/Bug journals reject and remain byte-identical whether their target exists or is absent; no generic cleanup is performed. A replay commit must contain exactly one matching Incident path and a canonical current record.

The final supported consumer is the separate exact-time v5 Incident profile. Published v4 remains immutable; do not infer that producer padding fixes every legacy v4 transition command.
