## Decal Pack 작업 기록 판단

- **판단 순서**: 등록 불필요 → 기존 기록 재사용 → 새 기록 필요 순서로 판단합니다. 파일·Git 상태를 바꾼다는 이유만으로 티켓을 만들지 않습니다.
- **등록 불필요**: 읽기 전용 조사·리뷰·계획 보고, 기존 변경의 커밋, 기존 커밋의 push·배포, 기존 범위의 테스트·빌드 재실행은 그 동작만을 위한 신규 등록을 하지 않습니다. 동작 계약을 바꾸지 않는 작은 변경(문구·스타일·문서·테스트 보강)은 커밋 메시지의 이유와 실제 검증 결과로 기록합니다. 파일 수나 세션 변경만으로 등록하지 않으며, 단순 커밋 안에 새 기능·계약 변경을 숨기지 않습니다. 이미 구현된 미등록 변경을 커밋 단계에서 발견하면 실제 발견 경위를 남기고 필요한 기록을 정리한 뒤 진행하며 선등록한 것처럼 소급하지 않습니다.
- **기존 기록 재사용**: 목표·완료 기준·출시 단위가 같은 Task·Work·Bug는 구현·검증·기록 보강을 같은 ID로 이어갑니다. 새 세션·커밋·테스트 실패·추가 단계만으로 Work를 만들지 않습니다. 닫힌 기록의 단순 실행·증거 보강은 종결 이력을 보존하고, 실제 재개가 필요하면 정식 reopen 경로를 사용합니다.
- **새 기록 필요**: 기존 기록에 포함되지 않는 독립적인 목표·완료 기준·후속 관리가 필요한 업무만 구현 전에 하나의 주 기록으로 등록합니다. 새 기능·저장 형식·권한·공개 프로토콜 계약 변경은 Task, 유계 개선은 Work, 독립 결함은 Bug, 실제 운영 장애는 Incident로 분류합니다. 보안·데이터 손상·운영 장애와 개발완료 뒤 독립 회귀는 분리합니다. 애매하면 실제 동작·저장 형식·권한·출시 영향을 확인하며, 불명확함 자체를 Work 생성 사유로 삼지 않습니다.
- **실행과 보고**: 등록 필요성과 실행 권한은 별개입니다. push·merge·배포·삭제·비밀값·비용·다른 저장소 접근의 승인 경계, Native 거절 시 우회 금지, source revision·정확한 대상 검증과 대상 밖 변경 보존을 유지합니다. 면제는 이유·변경·검증·실행 결과로, 등록 작업은 기존 ID와 결과로 보고하며 면제용 장부나 가짜 티켓을 만들지 않습니다. 사용자의 명시적 티켓 생성 요청은 존중합니다.
- **작성 경로**: 새 기록이 필요할 때만 종류·제목·분류 근거·기존 기록 재사용 여부·범위를 알리고 해당 ITS 스킬을 사용합니다. 외부 Host 등록은 설치된 `contracts/task-work-bug/its-register.mjs`와 광고된 capability를 사용하며 계약 번호를 직접 고르지 않습니다. 구 설치본은 자신의 검증된 고정 계약을 유지하고, 지원되지 않는 작업만 갱신 필요로 보고합니다. Decal 소유 세션은 광고된 Native 도구만 사용합니다.
- 프로젝트 출시 단계가 누락·null·`unset`이면 질문하거나 빌드를 멈추지 않고 `pre_live`로 해석합니다. 이 폴백은 저장값을 바꾸거나 배포·정산·비용·비밀값·외부 서비스 변경 권한을 열지 않으며, `live`는 명시적으로 저장된 경우에만 사용합니다.
- Work·Bug의 검증과 Smoke가 끝나면 `pre_live`는 `development_complete`에서 정상 종결하고 `release_ready`를 만들지 않습니다. 명시 `live`만 `release_ready`에서 실제 출시·앱 적용을 기다리며, 이 구분은 검증·정산·배포 승인 gate를 생략하지 않습니다.
